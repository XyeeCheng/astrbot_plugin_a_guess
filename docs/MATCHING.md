# v1.2.0 匹配规则与修复依据

游戏猜的是算法思路，不要求背题卡的唯一措辞。名称识别、解法是否适用、困难组合是否完整是三个独立判断。

## 名称与组合

- 二分、二分法、二分答案、二分查找、binary search 在本游戏按同一方法判定。原名称仍可出现在题卡解释中；换名称重复猜不扣次数，困难版不能靠“二分＋二分答案”凑两个方法。
- 扫描线、事件扫描、离线扫描、scanline、sweep line 支持互认。已知名称可附“算法／方法／法”，例如“扫描线算法”。
- 可写 `扫描线 + 线段树` 或 `扫描线和线段树`；“前缀和”不会被“和”字拆开。
- 普通版的题卡显式区分核心与辅助。1354B、888C 中二分是核心，可以单独猜中；612D 的排序是辅助，单猜排序不算正确。困难版仍要求一套解法的全部核心。
- 困难版一次提交完整组合。单猜“扫描线”可以显示“命中1/2，还缺1个”；先猜扫描线再猜线段树不会累计通关，需再次提交两者组合。
- “数学／图论／数据结构／搜索”等大类仍要求具体化且不扣次数。DFS与BFS、前缀和与差分、扫描线与排序没有被全局混为一类。


## v1.2.0 新增边界

- 否定或备选句（`not binary search`、`不用binary search`、`不使用 segment tree`）先澄清且不扣次数，不再通过英文模糊匹配变成正向答案。英文模糊匹配限制为短编辑距离；BFS/DFS 等短缩写仍严格区分。
- 支持末尾句号、问号、感叹号，以及 `a猜二分`、`a一把困难` 等紧凑命令。
- 946D 的 `DP`、`分组背包` 在本题映射为背包；846D 的前缀和在本题映射为二维前缀和；938D 接受最短路；01 字典树题接受字典树。598E 接受区间 DP／记忆化搜索表述，但仍须与枚举一并提交。
- 树形 DP、区间 DP、记忆化搜索等名称能识别，是否适用于题目仍按题卡规则判断，没有全局等同于任意 DP。
- 652D、863E 接受离散化作为辅助步骤；652D 的 `扫描线 + 树状数组 + 离散化` 可通关。
- 题卡内同义方法使用同一去重键，`DP + 分组背包` 不会在背包题中凑出两个核心方法。
- `input_audit` 每局只保留最近30条解析或有效猜测记录，含原输入、解析结果、是否扣次及规则版本；不记录 API 密钥，不改变有效操作时间。申诉处理有会话范围和管理员权限限制，不会自动修改历史输赢。
- 进行中对局保留开局题卡。缺少新版 `solution_rules` 的旧快照仍按旧组合规则判定；管理员 `a题库状态` 会提示使用旧快照。新开局应用新版核心规则。

## 根据对局反馈修订的题卡

以下多解分析是根据官方题意独立推导，并用小规模暴力对照验证。未声称所有替代写法均来自官方题解或已在Codeforces提交通过。

| 题目 | 修订与理由 |
| --- | --- |
| [652D](https://codeforces.com/problemset/problem/652/D) | 扫描线配树状数组或线段树，消去一个坐标并维护另一坐标的排名；也可用维护子树大小的平衡树。按左端点排序后，用归并分治统计右端点序列的右侧较小数，同样有效。保留排序组合，增加扫描线组合与分治组合。官方[题解](https://codeforces.com/blog/entry/43986)也说明排序后动态前缀计数的主方法。普通set的线性迭代计数不在此O(n log n)解释范围内。 |
| [632B](https://codeforces.com/problemset/problem/632/B) | 两次方向相反的线性DP，用“仍在翻转前缀／已经停止翻转”状态限制最多一次前后缀操作；增量模拟每个前后缀翻转也满足线性复杂度。新增DP、模拟；不可把允许随时重新开始的最大子段和当作该题DP。 |
| [873D](https://codeforces.com/problemset/problem/873/D) | 固定优先展开左子树，有预算即展开一个内部节点；每次恰多两次调用，直到预算用完。这是现有构造的贪心表述，新增贪心作为普通答案。 |
| [911A](https://codeforces.com/problemset/problem/911/A) | 对当前最小值位置，只保留离它最近的前一个最小值位置，较早位置不可能更优。接受该贪心和相邻位置双指针表述。 |
| [961E](https://codeforces.com/problemset/problem/961/E) | 按阈值依次加入符合条件的位置，用树状数组或线段树统计指定下标区间，是离线扫描线；补上同类漏收。 |
| [612D](https://codeforces.com/contest/612/problem/D) | 已有扫描线解法允许同时提交排序、差分辅助步骤，避免完整正确解法因多写实际步骤而失败。 |

652D 中的滑动窗口、静态前缀和，以及678C中的扫描线，不因名称能识别就自动认可。其他有效解法仍可通过 `a申诉` 提交供管理员核对。

## 测试与升级

`tests/test_matching_regressions.py` 保存去除会话标识后的题号和猜测用例。没有上传原始聊天记录。二分问题来自额外反馈，导出的这份对局中没有二分猜测；测试单独覆盖题库中所有含二分的答案。

`tests/test_reviewed_alternatives.py` 将632B的DP和增量模拟、652D的扫描线/排名树/归并计数、961E的阈值扫描、911A的相邻最小值策略，与独立暴力枚举比较。873D继续由原有递归调用数测试覆盖。

更新重载后，通用名称规则立即生效；已开局对局仍固定旧题卡、次数与截止时间。题卡新增解法从下一局生效。可让本局发起人 `a结束` 后 `a再来`；不会改写历史输赢，也不会清空数据库。
