# 菲比 · a一把

AstrBot 群聊算法竞猜插件，适用于 Ubuntu / Docker 部署。每局十次有效猜测，开场无题目提示，随后逐步展示中文题意与算法线索；普通版猜核心方法，困难版猜完整组合。

**v1.1.1 内置 200 道 Codeforces Educational 题卡：普通 150 道、困难 50 道。** 每道题均有九层提示、中文核心题意、小例子、解法说明、复杂度及原题链接。运行不需要额外 API Key，也不依赖模型临时生成题目。

v1.1.1 修复“二分过于宽泛”、扫描线漏收及部分正确算法组合被拒绝的问题，详见 [匹配规则与修复依据](docs/MATCHING.md)。已安装旧版时，在菲比插件管理页更新并重载本插件即可；进行中的题卡仍使用开局快照，新增解法从下一局生效，可先 `a结束` 再 `a再来`。

## 安装

要求：AstrBot >= 4.28.1；Python 使用 AstrBot 自带环境。开发验证环境为 Ubuntu 24.04 的 Python 3.12，以及 AstrBot 4.28.1 API。

在 **菲比的 AstrBot 管理页 → 插件 → 从链接安装** 填写：

```text
https://github.com/XyeeCheng/astrbot_plugin_a_guess
```

安装后启用插件。在群内 @菲比发送 `a一把`。完整 Ubuntu 操作和回滚说明见 [部署文档](docs/UBUNTU_DEPLOY.md)。

## 指令

| 指令 | 功能 |
| --- | --- |
| `a一把` / `a一把 普通` | 普通模式 |
| `a一把 困难` | 复合算法模式 |
| `a猜 前缀和` | 提交一个算法 |
| `a猜 二分答案 + 二维前缀和` | 提交算法组合 |
| `a提示` | 提前打开下一层提示，不扣次数 |
| `a进度` | 已开放线索、猜测记录和剩余时间 |
| `a结束` | 发起人或机器人管理员结束并揭晓 |
| `a再来` | 以最近一局模式开新局 |
| `a题意` / `a题解` | 游戏中只看已开放线索，结束后重看完整揭晓 |
| `a申诉 你的解法说明` | 保存尚未收录的解法供管理员核对 |
| `a帮助` | 玩法帮助 |
| `a题库状态` | 管理员查看题库数量 |

默认群聊需要 @机器人或使用 AstrBot 已配置的唤醒方式。`A一把` 也有效。新插件不注册裸“我猜／提示／结束”，可以与弗一把共存。

## 游戏规则

- 同一会话共享十次有效答案；第十次答对仍然获胜。不同群和平台实例相互隔离。
- 开场不展示题名、题号、链接、算法标签或题意。可盲猜，也可主动领取首段题意。
- 错误答案推进一层提示；前五层逐步展开题意，后四层给思路。主动要提示不扣猜测次数。
- 中英文别名、大小写、常见错字及较长英文拼写支持归一化。短缩写 BFS/DFS 严格区分；未识别或含糊答案先澄清。
- “二分／二分答案／二分查找”按同一个二分方法判定与去重，困难版中只算一个方法；“二分图”另算。支持“扫描线算法／scanline”等写法，也可用“和／与”连接算法名。
- 重复提交同一套答案、平台重复投递消息、冷却拦截都不重复扣次数。
- 普通题接受已收录的任一核心解法，同题多个已认可的单核心方法可以组合提交。困难题显示命中的方法与数量，但必须在一次答案中提交某套完整组合才能通关；缺少步骤与夹带无关方法会分别提示。
- 默认普通10分钟、困难15分钟，5分钟无有效操作结束；`a进度` 不延长时间。可在插件配置修改时间与冷却。
- 答对、十次用尽、主动结束和超时都会保存包含原题链接、中文题意及思路的结算。

## Ubuntu 持久化与 QQ 超时消息

SQLite 数据写在 AstrBot 插件数据目录 `astrbot_plugin_a_guess/a_guess.sqlite3`，不会写进源码题库。保留 AstrBot 的 data 卷即可跨容器重建保存进度。进行中的题卡随对局固定保存，题库更新不改变本局答案。

普通指令使用当前事件回复。QQ 官方群的超时结算，只有从真实群事件记录的场景和同一平台实例才尝试主动发送，且检查 QQ 返回的消息 ID；不把框架的布尔返回值当成送达。

**QQ 主动消息仍受平台权限和额度限制。** 没有群路由、非 QQ 官方群、无回执或网络结果不明时，结算保存在本地，下次该会话的游戏指令会展示；不会无限重发。可关闭 `proactive_timeout`，只使用下次交互展示结算。

## 题库与多解

- [题库一览](docs/QUESTION_BANK.md)
- [版本变更](docs/CHANGELOG.md) · [题源核对清单](docs/SOURCE_AUDIT.json)
- `questions.json` 保存中文重述、九层提示、多套答案、辅助步骤及来源。
- 题源归属与 rating 来自 Codeforces 官方元数据，题意按官方原题核对；算法解释为独立整理。原题难度不直接决定本游戏模式。
- 不是把 tags 列表当答案。普通模式包含少数高于初筛分数的单核心题，困难模式须提交组合。
- 不声称穷尽所有有效解法。`a申诉` 的记录存储于 SQLite `appeals` 表，管理员核对后可补充题卡；不会让大模型临时改变判题规则。
- 数据结构改动后请同步提升题卡 version。每套答案使用 `aguess/matcher.py` 的算法 ID；允许的辅助步骤放在 optional，不能随意把任意超集设为正确。

## 检查

无需 AstrBot 或第三方包即可运行核心测试：

```bash
python3 -m unittest discover -s tests -v
```

在已安装 AstrBot 的 Python 环境，可额外运行真实框架对象的适配冒烟检查（不会启动机器人或调用 QQ）：

```bash
python3 tests/smoke_astrbot.py
```

94项测试覆盖状态恢复、最后一次机会、并发去重、模糊匹配边界、复合答案与QQ回执；包含200道题的开局、九层提示和结算、全部别名核对，以及27道题的小规模独立算法对照。完整证据与未验证边界见 [验证记录](docs/VALIDATION.md)。
